[![앱 바로 실행](https://static.streamlit.io/badges/streamlit_badge_black_white.svg)](https://realmanufacturingai-gqmhke2ybcjhdrsndjsh2e.streamlit.app/)

제작자: 김태양. ABF 제조 이력 조사·통계·예방보전 검토를 연결하는 공개용 합성 데이터 시연 프로그램입니다. 실제 제조사·장비 형식과 사내 양산 정보를 포함하지 않습니다.

> 현재 로컬 검토판입니다. GitHub 업데이트 및 온라인 재배포는 보류 중입니다. 아래 실행 버튼은 기존 공개판으로 연결됩니다.

## 시작하기

위 **앱 바로 실행** 버튼을 누릅니다. 기존 배포 주소이므로 이 업데이트를 반영한 뒤 새 기능을 확인할 수 있습니다.

1. 왼쪽 **LOT ID 직접 검색**에서 `DEMO-0046`을 검색합니다.
2. 약액·공정 이력에서 기준 이탈과 Pre-bake·Cure·고온 Baking 온도 음영을 확인합니다.
3. AOI에서 Quad A–D와 유닛을 선택해 불량 위치를 확인합니다.
4. **6 · 종합·예방보전 → 종합·예방보전 분석 실행**을 누릅니다.
5. 설비별 불량 집계, 기준 이탈 관계, 시간순 검증·SHAP, 다음 3 LOT 추세를 확인합니다.
6. 조사 PDF 메뉴에서 현재 조사 결과와 실행한 종합 분석을 함께 내려받습니다.

앱은 처음 실행할 때 120 LOT의 합성 데이터를 생성합니다. 큰 JSON 파일을 별도로 업로드할 필요가 없습니다.

## 분석을 읽는 기준

목표는 LOT의 **ABF 대표 불량 비율**입니다. 전체 스캔 후 최초 대표 코드만 저장하는 조건이므로 다른 코드 유닛의 ABF 동반 여부는 알 수 없습니다. 같은 LOT이 여러 공정 설비를 거치므로 공정 간 불량 PCS를 합산하지 않습니다.

SHAP는 모델 예측을 설명합니다. 실제 원인 확률·인과 기여율·부품 고장 확률·잔여 수명을 뜻하지 않습니다. 초기 40% LOT 이후를 3개 시간 구간으로 나눠 검증하며 각 구간 시작 이후에 확인된 검사 결과를 해당 학습에서 제외합니다. 결측 대체값은 학습 구간에서만 계산합니다.

모델 MAE가 단순 평균 기준보다 10% 이상 개선되고 검증 불량/정상 LOT이 각각 3건 이상일 때만 우선순위의 보조 근거로 채택합니다. 이는 시연용 내부 채택 기준이며 외부 현장 검증을 대신하지 않습니다.

점검 우선순위: P1 현재 기준 이탈 → P2 추세 접근 → P3 기준 이탈과 ABF 대표 불량 반복 이력. 추세는 기준 경계 지수=1, 최근 8 LOT, R²≥0.6, 최대 3 LOT 연장 조건의 시나리오입니다. 점검·교체 주기는 제조사 근거가 없으면 수명으로 만들지 않습니다.

### 8D — 찾아낸 이상을 조치로 잇습니다

관리도와 분산분석은 "이상이 있다"까지만 말합니다. 현업에서는 그 다음이
본 업무입니다. 누가 언제까지 무엇을 하고, 효과가 있었는지 어떻게 확인하고,
다른 라인에 같은 문제가 없는지 누가 점검하는가.

```bash
python -m src.quality.run_eight_d
```

빈 양식이 아닙니다. D2 의 숫자와 D4 의 원인 후보를 사람이 적는 대신
`report/` 에 저장된 분석 결과에서 읽어옵니다. 그래서 모든 문장에 출처가
붙습니다.

| 읽는 파일 | 쓰이는 곳 |
| --- | --- |
| `quality_machine_summary.csv` | D2 얼마나, D4 설비 간 차이 |
| `quality_defect_rate_p_chart.csv` | D2 언제, D4 유출원인 |
| `quality_anova.csv`, `quality_tukey_hsd.csv` | D4 인자별 유의성과 효과 크기 |
| `quality_msa_variance_components.csv` | D4 측정 원인 배제 판단 |
| `quality_stratified_rule_signals.csv` | 드리프트 사례 선정 |
| `model_operating_points.csv` | D3 봉쇄조치의 선별 부하 |
| `quality_capability.csv` | D6 효과 확인 기준선 |

**발생원인과 유출원인을 나눕니다.** 형식만 따라 하면 D4 에 원인을 하나만
적고 끝냅니다. 정석은 두 갈래입니다.

- 발생원인(occurrence): 왜 불량이 생겼나
- 유출원인(escape): 왜 그걸 못 걸러냈나

둘은 시정조치가 다릅니다. 발생원인을 없애도 검출 체계가 그대로면 다음
불량도 똑같이 빠져나갑니다. 이 저장소의 사례에서 유출원인은 설비별 층별
관리한계만 운영한 점입니다. 나쁜 설비의 나쁜 수준이 그 설비의 기준이 되면
관리도는 영원히 관리 상태를 가리킵니다.

**사례 선정을 사람에게 맡기지 않습니다.** 어디에 8D 를 열지 고르는 일
자체에 편향이 들어갑니다. 눈에 띄는 설비, 최근 클레임이 있었던 설비가 먼저
선택됩니다. 두 기준을 코드로 고정했습니다.

1. 불량률이 전체 평균의 1.5배 이상인 설비
2. Nelson 판정에서 CRITICAL 신호가 잡힌 파라미터 — 불량이 아직 터지지
   않은 사례이고, 그쪽이 더 싸게 끝납니다

**파라미터 이탈은 공차 대비로 순위를 매깁니다.** 절대값으로 줄을 세우면
단위가 큰 파라미터가 항상 이깁니다. 공차 ±5 인 온도의 0.9 이탈보다
공차 ±1 인 압력의 0.22 이탈이 공정에는 위험합니다. 기준선도 다른 설비의
평균이 아니라 규격 중심으로 잡습니다. 설비가 셋뿐인데 하나가 드리프트
중이면 기준선이 그쪽으로 끌려가 멀쩡한 설비가 이상해 보입니다.

**하지 않은 것을 했다고 적지 않습니다.** D5 이후는 사람이 현장에서 실행해야
하는 단계입니다. 코드가 만들 수 있는 것은 '무엇을 목표로 어떻게 검증할지'
까지이고 '했더니 좋아졌다'는 결과가 아닙니다. 그래서 조치는 전부 미착수로
시작하고, D6 효과 확인은 현재 데이터를 매번 다시 계산해 기준선과 비교합니다.
조치 전이면 차이가 0 으로 나오며, 그것이 정확한 표시입니다. 확인하지 못한
원인은 '미확인'으로 남기고 미해결 항목에 모읍니다.

### 용어를 구분합니다

| 구분 | 출처 | 쓰이는 곳 |
| --- | --- | --- |
| 규격한계 LSL / USL | 설계와 고객이 정한 값 | Cp, Cpk, Pp, Ppk |
| 관리한계 LCL / UCL | 공정 변동에서 추정한 값 | 관리도, Nelson 판정 규칙 |

규격을 벗어난 것은 불량이고, 관리한계를 벗어난 것은 공정에 변화가 생겼다는
신호입니다. 조치가 다르므로 이름을 섞지 않습니다.
`src/process_spec.py` 의 키를 `lcl`/`ucl` 에서 `lsl`/`usl` 로 바로잡았습니다.

### 관리한계를 부분군 내 변동으로 추정하는 이유

전체 표준편차로 관리한계를 계산하면 부분군 간 변동까지 한계 폭에 포함됩니다.
공정에 평균 이동이나 추세가 있으면 그 변동이 한계를 넓혀, 정작 검출해야 할
신호를 감춥니다. 그래서 이동범위로 부분군 내 변동을 추정합니다.

```
sigma_hat = MR_bar / d2(2) = MR_bar / 1.128
UCL = X_bar + 2.660 * MR_bar
```

### Cp, Cpk, Pp, Ppk 를 함께 보는 이유

| 비교 | 뜻 | 필요한 조치 |
| --- | --- | --- |
| Cp 와 Cpk 의 차이 | 공정 평균이 규격 중심에서 치우친 정도 | 중심 조정 |
| Cp 와 Pp 의 차이 | 부분군 간 변동의 크기 | 설비 간 조건 정렬, 자재 LOT 편차 관리 |

Cp 는 좋은데 Pp 가 나쁘면 개별 배치는 균일하나 배치 간 산포가 큽니다.
이때 "산포를 줄여라"는 잘못된 처방입니다.

### 판정 규칙 위반을 기대 오경보와 비교합니다

판정 규칙은 관리상태에서도 오경보를 냅니다. 8,000 타점을 평가하면 규칙 1
하나만으로도 우연히 20건 이상 나옵니다. 그래서 관측 건수를 관리상태 기대값과
비교해, 우연 수준을 넘는 규칙만 신호로 분류합니다.

기대 오경보 확률은 이항분포 공식이 아니라 몬테카를로로 실측했습니다.
규칙 3, 4 는 연속 차분의 부호를 보는데 i.i.d. 정규 데이터에서도 인접 차분끼리
상관계수 -0.5 의 음의 상관을 가지므로, 독립을 가정한 공식이 맞지 않습니다.
규칙 4 의 경우 이론값 0.000244 와 실측값 0.001655 가 약 7배 차이납니다.
규칙 1 의 실측값 0.002688 이 이론값 0.0027 과 일치하는 것으로 시뮬레이션
자체를 검증했습니다.

### 계수형 데이터는 p 관리도로 봅니다

수율과 불량률은 이항분포를 따르므로 I-MR 관리도에 올리면 정상 LOT 과 불량
LOT 이 두 개의 봉우리를 만들어, 모든 불량 LOT 이 규칙 1 위반으로 잡힙니다.
이상 신호가 아니라 차트 선택이 틀린 것입니다. 불량률은 `p_chart` 로 봅니다.

| 현장 용어 | 통계 용어 | 의미 |
| --- | --- | --- |
| 같은 작업자 반복 측정 산포 | 반복성 EV | 계측기 자체의 산포 |
| 작업자 간 편차 | 재현성 AV | 작업자가 바뀔 때 생기는 산포 |
| 측정 신뢰성 | %GRR | 10% 미만 적합, 10~30% 조건부, 30% 초과 부적합 |
| 구별력 | ndc | 5 이상이어야 구간 판정 가능 |
| 공차 대비 측정 산포 | %P/T | 규격이 좁은 특성에서는 %GRR 보다 중요 |

AIAG MSA 4판의 ANOVA 법을 씁니다. 범위법보다 정확하고 부품과 작업자의
교호작용을 분리할 수 있습니다. 교호작용이 유의하지 않으면(p > 0.25)
오차항에 통합해 재계산합니다.

### 설비 간 비교는 ANOVA 다음에 Tukey HSD

설비가 3대면 쌍별 비교가 3번, 5대면 10번입니다. 각 비교를 유의수준 5%로 하면
"어느 하나라도 유의하게 나올" 확률이 3번일 때 14%, 10번일 때 40%까지
올라갑니다. 그래서 순서를 지킵니다.

1. 일원분산분석으로 "어딘가 차이가 있는가"를 판정
2. 유의하면 Tukey HSD 로 "어느 쌍이 다른가"를 확인 (전체 유의수준 5% 유지)
3. Levene 검정으로 등분산 가정이 깨지면 Welch ANOVA 로 판정

### 불량 예측 모델의 평가 기준

불량률이 13% 수준인 데이터에서 accuracy 는 "전부 정상으로 예측"만 해도
87%가 나옵니다. 그래서 다음을 함께 보고합니다.

- PR-AUC 와 더미 모델(전부 정상 예측) 대비 배수
- 판정 임계값을 0.5 로 두지 않고 목표 검출률에서 결정
- 과검률(정상을 불량으로 의심)과 미검률(불량이 그대로 유출)을 분리
- 목표 검출률별 운전점 선택표 (`report/model_operating_points.csv`)
- L1 규제 로지스틱 회귀 비교군 (선형 모델이 비슷하면 신호가 단순하다는 증거)
- 5겹 계층 교차검증 PR-AUC 평균과 표준편차

`models/random_forest_defect_model.joblib` 에는 모델과 함께 판정 임계값을
저장합니다. 임계값을 분리해 두면 추론 시점에 0.5 가 다시 쓰입니다.

## 데이터 생성기

`src/data/generate_process_data.py` 는 다음 구조를 의도적으로 심습니다.
분석 도구가 실제로 무언가를 찾아내는지 검증하기 위한 것입니다.

| 심은 구조 | 검출되는 도구 |
| --- | --- |
| Press2 온도와 압력이 동시에 부족할 때의 교호작용 | 트리 모델, JMP 교호작용 분석 |
| PRESS_02 의 압력 저하와 산포 확대 | ANOVA + Tukey HSD, Levene 검정 |
| PRESS_03 의 Cure 온도 점진적 하강 | Nelson 규칙 2, 3, 5, 6, 8 (규칙 1 로는 안 잡힘) |
| MODEL_C 의 높은 박리 민감도 | 모델별 불량률 비교 |
| 작업자 OP_C 의 계통 편향과 부품 교호작용 | Gage R&R |
| 계측기 편향 +0.045, 기울기 0.978 | 편향·선형성 분석 |

박리 발생률은 `TARGET_LOT_DEFECT_RATE` 설정값에 맞춰 로짓 절편을 이분법으로
자동 보정합니다. 계수를 조정할 때마다 불량률이 흔들리는 것을 막습니다.

`src/data/generate_msa_data.py` 는 시료 10개 x 작업자 3명 x 반복 3회의
균형 교차 설계와, 기준값이 알려진 표준 시료 측정 데이터를 생성합니다.

## 검증

```bash
python -m pytest -q
python -m src.investigation.evaluate_scenarios
```

품질 분석 모듈은 `tests/test_quality_*.py` 6개 파일에서 검증합니다.
ANOVA 와 Tukey HSD 는 `scipy.stats.f_oneway`, `scipy.stats.tukey_hsd`,
`scipy.stats.levene` 의 결과와 대조하고, Gage R&R 은 제곱합 분해 항등식과
분산 성분 회수로 확인하며, Nelson 판정 규칙은 규칙별 발동/미발동 데이터와
몬테카를로 오경보율로 검증합니다.

8D 는 통계 계산이 아니라 문서 생성이라 검증 방향이 다릅니다. 숫자가 맞는지
보다 거짓을 말하지 않는지를 봅니다. 실행하지 않은 조치가 완료로 표시되지
않는지, 확인하지 않은 원인이 확인됨으로 표시되지 않는지, 분석 결과에 없는
숫자를 지어내지 않는지, 단위가 다른 파라미터를 절대값으로 비교하지 않는지를
검증합니다.

합성 데이터 검증 결과는 `docs/predictive_validation.json`에 수록했습니다. 모델의 실공정 정확도나 인과성을 주장하지 않습니다. 기존 통계·ML 학습용 화면은 별도 모드로 보존했습니다.

## 저장·공개 범위

- 엔지니어 검토 기록은 브라우저 세션에 보관됩니다. 종료 전 JSON 백업을 받으세요.
- 시료 이력의 로컬 SQLite DB는 `instance/`에 저장되며 Git에 포함하지 않습니다.
- 공개 데모에서는 가상 이름·가상 시료만 사용하세요. 처리자 이름 입력은 로그인 인증이 아닙니다.
- 임시 디스크 기반 호스팅에서는 시료 DB가 재배포 후 보존되지 않을 수 있습니다. 실제 공동 운영에는 인증과 영구 DB가 필요합니다.
- 실제 제조사/형식, 사내 문서, 개인 이름이 포함된 운영 자료를 공개 저장소에 업로드하지 않습니다.

## 구현 범위

Library는 누적 사례를 검색·재사용합니다. 외부 AI는 OpenAI API 키·모델 설정 후 선택 근거를 확인하고 요청할 때만 호출합니다. 외부 논문 자동 수집, 자동 재학습, PLC 실시간 연결·제어는 아직 연결하지 않았습니다. 설비 비교는 관찰 자료이며 자동 배정 기능이 아닙니다.
