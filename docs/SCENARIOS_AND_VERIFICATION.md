# 원인별 사례와 확인시험 흐름 · Ver1.0

2026-09-25 업데이트. 제작자 김태양.

## 시작

왼쪽 **원인별 사례·반례 열기**를 펼쳐 사례 이름을 누릅니다. 모델과 LOT가 함께 바뀝니다. ‘근거·확인시험’에서 등록 근거를 확인하고, ‘검토·보고서’에서 실제 확인시험 결과를 기록합니다.

|DEMO-0021|밀착 압력·시간 이탈|압력/유지시간 설정 대비 실측 편차와 Quad 가장자리 불량을 대조|

사례 설명과 기대 결과는 시연·시험용 목록에만 있습니다. 조사 규칙은 LOT의 사례 이름이나 평가 정답을 읽지 않습니다. 데이터의 변화와 검사 기록을 이용합니다. 이 데이터는 공정 메커니즘을 실증한 자료가 아니라 조사 절차를 검증하는 합성 사례입니다.

## 확인시험 → 후보 판단

‘이번 기록에 실제 확인시험 결과를 포함’을 선택하고 다음을 입력합니다.

1. 검증할 후보, 실시한 시험 방법, 검증 범위·비교 조건·표본.
2. 실제로 실시한 조치와 결과, 증거 문서/측정값, 담당자.
3. 엔지니어 판정: **지지 / 반증 / 판단 불가**.
4. 검토 기록 추가. 같은 데이터·LOT·층·면·회차·조회 시점의 시험을 모아 판단을 표시합니다.

|누적 시험 판정|표시|
|---|---|
|지지만 있음|후보 유지|
|반증만 있음|검토 범위에서 제외|
|지지와 반증이 함께 있음|상충 결과 · 재검증|
|판단 불가가 섞였거나 판단 불가만 있음|판단 보류|

후보 판단은 엔지니어가 입력한 판정의 보수적 집계입니다. 결과 문장을 AI가 해석해 원인을 확정하지 않습니다. 여러 검증 범위가 섞여 상충하면 다시 확인해야 합니다. 제외는 입력한 시험 범위에 한정되며, 실제 원인 부재를 보증하지 않습니다. 잘못 입력한 시험도 삭제로 지우지 않고 추가 기록으로 남길 수 있습니다. 현재는 기록 취소/개정 연결 기능이 없어 상충 기록은 재검토 대상으로 유지됩니다.

신규 ‘검증 완료’ 기록에는 담당자·실제 결과·증거와 확인시험이 필요합니다. 과거 백업 형식은 계속 읽을 수 있지만, 과거 기록이 새로운 완료 요건까지 만족한다고 재인증하지 않습니다.

## 조치 후 효과 확인

선택 입력에서 조치 전/후 검사 PCS와 불량 PCS, 같은 모델·층·면·검사 기준 및 기간, 필요한 최소 검사 PCS를 입력합니다. 불량 PCS가 검사 PCS보다 많으면 저장을 거부합니다.

- 전후 불량률과 차이(%p)를 계산합니다.
- 전후 중 하나라도 지정 최소 표본보다 작으면 ‘표본 부족 · 추가 수집’입니다.
- 표본 조건을 만족하고 불량률이 낮아지면 ‘감소 관찰 · 효과 확정 아님’입니다.
- 그 외에는 ‘감소 미확인 · 재검토’입니다.

기본 최소 30 PCS는 화면 시연값이며 통계적 표본 설계가 아닙니다. 수량·비교 조건은 사용자가 입력하므로 동일성이나 생산 기간을 자동 검증하지 않습니다. 통계적 유의성, 회귀 보정, 설비/자재별 독립 효과 분석을 수행했다는 뜻이 아닙니다.

## 보고서와 복구

확인시험 방법·범위·결과·증거·담당자, 누적 후보 판단과 조치 전후 관찰 결과가 한글 표로 보고서에 포함됩니다. 원시 JSON과 개발 명령을 본문에 표시하지 않습니다. 검토 이력 백업에도 새 필드가 포함되며 손상·동일 ID 충돌 검사를 유지합니다. 종료 전 백업을 내려받으세요.

## 검증 범위

전체 58개 자동 테스트. 사례 9종 × 난수 조건 3종의 수용 검증 27/27 통과. 기대한 표시·분모·상충 처리·필수 증거·복구·보고서를 확인했습니다. 결과 파일은 `scenario_validation.json`입니다.

이 결과는 개발자가 작성한 시나리오에 대한 수용 검증이며 독립 현업 검증이나 실제 원인 진단 정확도가 아닙니다. 다음에는 사용자가 사전 기대 결과를 정한 새 사례와 수작업 대비 조사 시간/근거 누락 비교가 필요합니다. 시간 측정 결과는 아직 없습니다.
