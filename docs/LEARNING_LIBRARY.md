# 개선·지식·설비 Library — 로컬 검토판

GitHub 배포는 보류 상태입니다. 기존 프로그램 안의 `7 · 개선·지식·설비 Library`에 세 가지 작업을 연결했습니다. 프로그램을 분리할 필요는 없지만, 향후 설비 수집 서비스는 화면과 별도로 운영해야 합니다.

## 1. 개선 실행과 지식 축적

1. 조사할 LOT을 선택합니다.
2. Library에서 새 사례를 선택하고 모델, LOT, 자재 규격, 설비 호기, 담당자를 입력합니다.
3. As-is 현상/원인 가설, 실제 조치, To-be 목표 및 사전 합격 기준을 적습니다.
4. 전후 기간·모델·자재·층·면·검사 기준과 검사 PCS/ABF 대표 불량 PCS를 넣습니다. 서로 다른 검사 범위를 합하지 않습니다.
5. 계획→진행 중→검토 완료로 갱신합니다. 완료에는 실제 결과, 증거, 검토자가 필요합니다.
6. 사례 검색에서 전후 불량률과 %p 변화, 막대그래프를 확인하고 HTML 보고서를 받습니다. 브라우저 인쇄→PDF 저장이 가능합니다.
7. 검토 완료 사례는 기술자료 검색 대상에도 들어갑니다. 미완료 의견은 검증 지식으로 승격하지 않습니다.

기록 저장은 로컬 `instance/engineering_library.sqlite3`입니다. 수정 시 개정 번호로 동시 수정 충돌을 감지합니다. 사용자 이름은 인증이 아니며 접근 제어·전자서명은 없습니다. Library JSON 백업은 자료 본문을 포함하므로 개인적으로 보관합니다. 복원은 같은 ID의 다른 내용을 덮어쓰지 않고 충돌을 알립니다.

자동 재학습은 없습니다. 현재의 발전은 검토 사례 검색·재사용입니다. 다음 모델 개정에는 독립적인 시간순 검증, 기존 모델 대비 평가, 승인 및 되돌리기 기준을 마련해야 합니다. 입력한 개선 목표와 효과 판정은 자동으로 인과성을 입증하지 않습니다.

## 2. 기술자료

TXT/Markdown(UTF-8) 또는 원문 발췌를 제목, 출처·페이지, 근거 유형과 함께 등록합니다. 질문하면 문자 n-gram TF-IDF로 관련 구절을 검색해 원문과 출처를 보여줍니다. 검토 완료 사례도 함께 찾습니다. 기본 검색은 로컬에서 동작합니다. 선택적으로 검색 근거를 외부 LLM에 전달하는 RAG 검토 초안을 요청할 수 있습니다.

현재 미지원: PDF 본문/OCR 자동 추출, DOI 수집, 유료 논문 접근, 인터넷 상시 탐색, 신규 소재 자동 추천. 이 기능들은 출처·사용 권한·대상 분야 필터, 중복 문서 버전 관리와 인용 검증을 갖춘 다음 단계입니다. 문서 안의 지시는 실행하지 않습니다. 홍보자료를 학술 근거와 동일한 수준으로 취급하지 않습니다.

## 3. 설비 지도와 상태

PNG/JPEG 도면을 올리고 부품을 X/Y 0~100%로 배치합니다. 도면 해시, 내부 설비 형식, 호기, 부품, 센서 태그, 관리 한계를 저장합니다. 도면 원본은 서버에 보관하지 않으므로 다음 방문에는 같은 이미지를 다시 선택합니다. PDF/CAD 도면은 우선 이미지로 내보냅니다.

동일 내부 형식의 설비 호기와 연결된 개선 사례를 함께 확인합니다. 사례의 대상 설비와 도면의 호기 ID를 동일하게 기입해야 합니다. 구조적 결함을 도면만 보고 자동 진단하지 않습니다.

측정 기록은 `[{"time":"2026-09-25T10:00:00+09:00","value":5.3,"quality":"GOOD"}]` 형식입니다. 선택한 부품에 연결하여 재생합니다. 단위와 관리 기준을 확인하세요. 기준 시각보다 60초 이상 오래되면 지연, 미래 시각이면 오류, GOOD 이외면 판정을 보류합니다. 예시는 합성 값이며 실제 모터 수명 예측이 아닙니다.

실제 온라인 연결은 OPC UA 등 읽기 전용 수집 → 시간·단위·quality 검증 → 저장/버퍼 → 분석 → 화면 순서로 분리하는 것이 적합합니다. 센서 원시 태그, 샘플링 주기, 정상 부하별 기준, 통신 중단 정의, 고장/수리 이력 없이는 Edge AI의 고장 예측 성능을 주장할 수 없습니다.

## 다음에 필요한 정보

- 익명화한 도면 한 장(가능하면 직접 그린 개념도), 내부 호기·부품·센서 연결표
- 모터 전류 등의 단위, 정상 가동 모드, sampling 주기, quality 코드 의미
- 개선 사례의 전후 구간, 비교군, 확인시험, 조치 일시, 재발 확인 기간
- 공개 가능한 기술자료 3~5건과 원문/사용 권한

자료가 없으면 현재의 합성 시연과 수동 자료 등록으로 검토할 수 있습니다. 실제 현장 연결을 요구하지 않습니다.

## 외부 AI 설정과 사용 순서

1. `기술자료·근거 검색`에서 자료 또는 검토 완료 사례를 먼저 검색합니다.
2. `외부 AI 연결 설정`을 펼칩니다. OpenAI API 키와 해당 계정에서 접근 가능한 모델 ID를 입력합니다. API 키는 대화창으로 보내지 않습니다.
3. 전송할 발췌를 선택합니다. 질문, 제목, 출처, 최대 5개 발췌(각 최대 900자)와 지시문을 확인합니다.
4. 전송·API 비용 확인 체크 후 `선택 근거로 외부 AI 검토 초안 요청`을 누릅니다.
5. 원문 근거 번호와 AI 초안을 대조합니다. 초안은 자동으로 확정 사례에 저장하거나 학습하지 않습니다.
6. 종료할 때 `세션 API 키·응답 지우기`를 누릅니다. 키는 파일·DB·GitHub 패키지에 저장하지 않습니다.

현재 연결 대상은 OpenAI Responses API입니다. 다른 공급자 및 로컬 LLM은 아직 연결하지 않았습니다. 유효한 API 키가 제공되지 않아 실제 유료 호출은 수행하지 않았고, 테스트 응답을 이용해 요청 형식·인용 번호·오류 처리를 검증했습니다. 모델별 접근 권한과 출력 한도는 실제 계정에서 확인해야 합니다.

`store=false`를 사용하지만 이는 모든 서비스 측 보관을 없앤다는 뜻이 아닙니다. API 사용 비용과 자료 전송 여부를 검토하고 승인된 자료만 보내세요. 원문과 맞는 의미인지까지 자동 보증하지 않습니다.

공식 구현 근거: https://developers.openai.com/api/docs/guides/migrate-to-responses
데이터 처리 안내: https://developers.openai.com/api/docs/guides/your-data
