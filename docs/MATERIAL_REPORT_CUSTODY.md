# 자재·보고서·시료 관리 업데이트 (Ver1.0)

## 달라진 흐름
- 제조 이력 조사 → AOI 위치 → 불량 유닛 선택 → 불량 시료 불출 요청.
- 검사자가 시료 불출·수령 관리에서 실제 구역을 입력하고 불출 완료 처리.
- 엔지니어가 수령 완료 처리하면 현재 보관자가 표시됨. 회수 후 반납 완료까지 기록 가능.
- 동일 데이터·LOT·PANEL의 활성 요청은 하나만 허용. 층/면/유닛은 요청 위치 정보이며 PANEL 전체가 이동 단위.
- 이미 처리된 이전 화면으로 재처리하면 저장을 거부하고 새로고침을 안내함.
- 취소/반납 후에는 새 요청 가능. 기존 이력은 보존.

## 자재 기준
사용자 확인 기준: 최초 냉동 최소 48시간 → 냉장 최소 24시간 → 해동 최소 12시간 → 사용.
재사용은 냉장 최소 24시간 → 해동 최소 12시간. 최대 3회 해동. 세 번째 해동 후 재냉장 불가.
실제 사용하는 자재 개체(material_unit)당 최대 6 LOT. 6 LOT 사용 완료 시 잔량 없음·사용 종료.
모델 지정 자재(model_materials), 공급사 자재 LOT(material), 물리적 개체(material_units)를 구분.
기존 자재 공유는 공급 LOT 연결 관계였으며 모델 지정 자재 검사와 취급 시간 판정이 새로 추가됨.
시간 기준은 취급 단계별 시작/종료 기록 기준. 해당 LOT 사용 완료 이후 이벤트는 원인 분석에서 제외.
모델 불일치·순서 위반·대기시간 미달·해동 횟수 초과·사용 종료 후 추가 취급을 경고.
Pore/Void 원인 확정은 하지 않으며 단면/추가 분석을 제안함. 설비를 물리적으로 정지하는 기능은 아님.
공급사 LOT 예시 묶음을 확대하여 동일 개체 6 LOT와 3회 해동 시연이 가능하도록 조정했음.
기존 데이터는 자재 개체가 없으면 기록 부족으로 표시. 실제 자재 사양이나 양산 승인 기준을 주장하지 않음.

## 보고서
조사 보고서 PDF 메뉴는 같은 브라우저 세션에서 가장 최근에 조회한 모델·LOT·층·면·검사 회차를 사용.
새 세션은 제조 이력 조사를 먼저 열어야 함. 보고서에는 조회 범위를 명시.
요약, Quad 유닛 PASS/FAIL 배치도, 표, 연속 온도 그래프, 원인 후보, 자재 이력, 유효한 검토/확인시험/시료 보관 상태를 포함.
한글 폰트 포함. PDF는 메모리에서 생성하며 서버 공유 보고서 파일을 덮어쓰지 않음.
HTML 편집 보고서도 계속 제공. PDF 자체의 본문 편집 대신 HTML 초안을 수정해 사용.
기존 학습용 PDF/Pipeline 페이지 원본은 src/legacy_pages에 보존. 메인 메뉴에서는 현재 앱 업무만 제공.

## 저장과 배포
시료 이력은 기본 instance/custody.sqlite3에 영구 저장(동일 로컬 디스크의 재시작 기준).
환경변수 INVESTIGATION_CUSTODY_DB로 영구 볼륨 경로 지정 가능. DB/이름/실제 시료 이력은 Git에 올리지 말 것.
시료 JSON 내보내기는 열람·보관용이며 자동 복원 기능은 아님. 복구는 앱을 종료한 상태에서 DB 파일을 백업/복사.
처리자 이름은 입력값이며 인증/전자서명 아님. 서버 접근자는 다른 사람 이름을 입력할 수 있으므로 실제 운영용 접근 통제가 아님.
공개 데모는 가상 이름·시료만 사용. 화면 안내는 앱 내 알림이며 이메일/메신저를 자동 발송하지 않음.
Streamlit Community Cloud 등 임시 디스크 환경에서는 재배포 시 DB가 소실될 수 있음. 실제 운영 전 인증·역할 권한과 영구 DB 연결 필요.
기존 엔지니어 검토 기록은 여전히 브라우저 세션 저장이므로 종료 전 JSON 백업 필요.
이 패치는 GitHub에 자동 업로드하거나 배포하지 않음.

## 적용
1. 현재 앱의 검토 기록을 JSON 백업하고 앱 종료.
2. 기존 프로젝트를 복사해 보관. ZIP을 프로젝트 루트에 덮어쓰기(기존 data/models/Git 이력 보존).
3. requirements.txt 기준 의존성 설치. assets/fonts 폴더와 OFL.txt도 반드시 함께 반영.
4. python -m streamlit run src/dashboard/app.py 실행.
5. DEMO-0045에서 자재 탭 확인. DEMO-0047은 해당 개체의 6 LOT 사용 종료 예시.
6. AOI에서 FAIL 유닛 요청 → 시료 관리에서 불출 → 수령 → 반납을 가상 이름으로 확인.
7. 조사 PDF 다운로드 후 현재 LOT와 검사 범위가 일치하는지 확인.
8. GitHub 업로드 전 instance/ DB와 실제 이름이 없는지 확인. 배포 후 새 세션에서도 화면·PDF를 점검.

## 검증
전체 자동 테스트 63개 통과. 변경 후 자재/시료/PDF/UI 집중 검사 6개 통과.
기존 9개 원인/반례 × 3 seed = 27/27 통과.
PDF 4페이지를 이미지로 렌더링하여 한글, 표, Quad 배치도, 온도 그래프 잘림 여부 확인.
보고서와 시료 관리 페이지 이동 확인. 시료 동시 처리의 오래된 revision 저장 거부·중복 PANEL 요청 차단 검증.
